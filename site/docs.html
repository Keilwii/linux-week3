Commands I used

date '+%Y-%m-%d %H:%M:%S %Z'

Prints the date and time in a format I chose. %Z adds the time zone name. The server runs in UTC.

uptime -p

Uptime in plain words ("up 6 days, 13 hours..."). uptime -s gives the boot time instead.

df -P / | awk 'NR==2 {gsub("%", "", $5); print $5}'

df shows the root filesystem usage, and the pipe sends it to awk. awk takes line 2 (line 1 is the header), drops the % sign from column 5 and prints just the number. -P keeps the output on one line, so the columns are always in the same place.

free -m | awk '/^Mem:/ {print $2, $7}'

RAM in megabytes. awk picks the line starting with "Mem:" and prints total (column 2) and available (column 7).

crontab -l

Shows my crontab, to check the schedule is installed.

How it works

Script (status.sh): collects the values with command substitution ($(...)) into variables, then writes the html with a heredoc. It writes to a temp file first and then mvs it over index.html, so nginx never serves a half-written page. Nginx already serves /var/www/week-1 from week 1, so writing into /var/www/week-1/viikko3/ was enough and I didn't need to change the nginx config.

Disk status: the function disk_status takes the usage percentage, and if (( pct >= 80 )) prints WARNING, otherwise OK. Running ./status.sh --test N only prints the status for N, so I could test the logic without touching the real value or filling the disk.

Schedule: a user crontab line * * * * * /home/kalle/linux-week3/status.sh runs the script every minute. The cron service is enabled in systemd, so it starts on boot and the crontab keeps working after a reboot. Errors go to ~/status-cron.log (empty so far). The page also refreshes itself every 60 seconds.

Problem I ran into

I used mktemp for the temp file, but mktemp creates files with permissions 600 (only the owner can read). Nginx runs as www-data, so it can't read a file like that. I tested it with a test file made by mktemp: the browser got 403 Forbidden, and after chmod 644 it loaded fine (200). So the script does chmod 644 on the temp file before moving it into place. Learned that file permissions matter even when the folder itself is readable.
